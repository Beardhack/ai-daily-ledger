# Agents Move From Schedules to Events

## Triggered work, delegated sign-in, local runtimes, simulation confidence, and AI-native development

**AI Daily Ledger - August 26, 2026 - Daily edition**

AI products are acquiring the machinery needed to act over time and across software boundaries. ChatGPT Work added connector-triggered tasks and delegated website sign-in. Perplexity announced a local agent runtime for NVIDIA DGX Spark. Simile described a confidence model for simulations, while Anthropic published an artifact-centered software-development playbook. Engineers also reported that coding agents can supervise long training jobs when monitoring and context compaction work reliably.

Most items are product announcements, practitioner accounts, or commentary. They establish what vendors say is available and what individual users report. They do not establish comparative reliability, security, or economic value. The useful engineering questions concern event semantics, credential boundaries, reproducible local operation, calibration, and the evidence stored throughout a development loop.

## Connector events turn tasks into persistent automation

[ChatGPT announced that Plus and Pro users can trigger tasks when Slack, Gmail, or GitHub changes, and said scheduled tasks are rolling out to Free users](https://x.com/ChatGPT/status/2092335329110004140). [Greg Brockman described the feature as triggered tasks](https://x.com/gdb/status/2092430694253572216). These are vendor statements about availability. The feed excerpts do not specify delivery guarantees, retry behavior, event filters, or service-level limits.

An event-triggered task has a different failure surface from a timer. Connectors can deliver duplicate events, reorder them, or omit intermediate state. A task can also start after the underlying object has changed again. Implementations need stable event identifiers, idempotent handlers, explicit checkpoints, and a record of the source state used for each decision. Users need controls for which repositories, channels, threads, and message classes may wake an agent.

The product boundary now includes the trigger and the resulting action. Evaluation should measure missed and duplicate executions, time from event to completion, connector outages, authorization changes, and recovery after partial work. Audit records should bind the incoming event, retrieved context, model version, tool calls, approvals, and final output into one trace.

## Delegated sign-in creates a credential control plane

[Sam Altman relayed ChatGPT's claim that ChatGPT Work can use a computer and browser to sign in to websites without the model seeing the username or password](https://x.com/sama/status/2092519459135095147). [A separate ChatGPT post said website login is rolling out on web and mobile for Plus, Pro, and Business users](https://x.com/ChatGPT/status/2092335330976497830). This is a vendor security claim. The posts do not expose the credential architecture or an independent assessment.

Keeping secrets outside model context reduces one direct disclosure path. The surrounding system still has to prevent credential replay, session theft, confused-deputy actions, and access beyond the user's request. A browser session can authorize consequential actions even when the agent never reads the password. Security therefore depends on the scope and lifetime of delegated sessions, origin binding, isolation between tasks, and confirmation at sensitive boundaries.

Useful documentation would specify where credentials and cookies reside, which component can request their use, how sessions are revoked, what appears in logs, and whether websites can distinguish delegated access. Red-team tests should include malicious pages, cross-origin redirects, deceptive consent screens, stale sessions, and attempts to transfer authenticated state between tasks.

## Local agent runtimes combine privacy with capacity limits

[Johnny Ho highlighted Perplexity's announcement of Portable Computer on NVIDIA DGX Spark, described as a fully local runtime containing the orchestrator model, subagent model, and agent harness](https://x.com/randomjohnnyh/status/2092501419027022201). [Daniel Jeffries amplified the same announcement](https://x.com/Dan_Jeffries1/status/2092307028563669221). These posts repeat a vendor claim. No independent latency, quality, energy, or workload comparison appeared in the reviewed material.

A local runtime can keep prompts, retrieved documents, intermediate state, and tool traces on controlled hardware. It also makes memory capacity, thermal behavior, model quantization, and software compatibility part of the application contract. Hybrid designs add routing decisions: the system must disclose which work stays local, what can move to a cloud model, and how a task behaves when either side is unavailable.

Evaluation should report model builds, precision, context length, peak and sustained memory use, time to first token, throughput under concurrent subagents, power draw, and task success. Reproducible packaging matters as much as peak speed. A local agent is operationally useful when updates, sandboxing, rollback, and data retention can be administered without losing the privacy property that motivated deployment.

## Simulations need calibrated confidence estimates

[Percy Liang called confidence central to trustworthy simulation and pointed to Simile's account of training separate simulation and confidence models](https://x.com/percyliang/status/2092302845987225809). His post is expert commentary on a company research report. The feed excerpt provides no calibration curve, held-out benchmark, or comparison with simpler uncertainty estimates.

Simulation errors are difficult to detect because a plausible trajectory can remain internally coherent while misrepresenting the real system. A confidence score is useful only when it predicts error on the decisions users will make. Calibration must be tested under distribution shift, rare events, interventions, and long rollouts. Aggregate accuracy can conceal severe overconfidence in precisely the cases that carry the highest cost.

Reports should pair confidence with empirical coverage: among forecasts assigned a given probability or interval, how often does the outcome fall inside it? Selective prediction tests can show whether abstaining on low-confidence cases improves retained performance. Developers also need provenance for training data, scenario assumptions, and changes to the simulated environment so confidence estimates are not treated as timeless properties.

## AI-native development depends on durable artifacts

[Richard Seroter summarized Anthropic's AI-native software-development playbook as an artifact-driven loop across familiar lifecycle stages](https://x.com/rseroter/status/2092351306799120526). [Viv reported that improved process monitoring and compaction let coding agents work directly with long-running model-training jobs](https://x.com/Vtrivedy10/status/2092502960873861631). The first is commentary on vendor guidance; the second is a practitioner account without published controlled results.

Both accounts place persistent evidence at the center of agent work. Requirements, plans, patches, test results, training metrics, and incident records give later model invocations a state they can inspect. Monitoring converts a long-running process into observations and decisions. Compaction determines which observations remain available after the context window changes. Failures in either layer can make a capable model act on obsolete or incomplete state.

Teams can test the workflow by replaying tasks from stored artifacts, measuring recovery after interruption, and comparing agent decisions before and after compaction. Training supervision needs declared alert thresholds, sampled logs, checkpoint lineage, resource limits, and a human escalation path. The development loop becomes auditable when every transition has an input artifact, an observed result, and a recorded decision.
